## 🎯 About Me

```yaml
role: Product Manager (in progress) × Software Engineer × AI Builder
focus: Turning self-initiated AI automation into measurable product outcomes
philosophy: "Ship, measure, iterate — the code is just how the product thinking gets proved."
```

I'm a final-year Computer Science and Engineering student who decided early that I didn't want to just *build* features — I wanted to own the **why** behind them. That's led me to spend the last year treating every side project like a product: identifying a real user problem, scoping an MVP, shipping it with AI/automation tooling, and coming back with metrics instead of just a repo link.

I sit at an intersection that's rare for a fresher — **technical enough to prototype fast with AI agents and full-stack tools, product-minded enough to frame every build around user impact, retention, and ROI.** I'm not choosing between PM and engineering; I'm using engineering as leverage to become a sharper, faster, more credible PM.

**🟣 Open To:** APM / PM Internships · Product Analyst Roles · AI Product Roles · Cross-functional Collaboration

| Attribute | Detail |
|---|---|
| **Stack** | n8n, OpenAI API, Webhook triggers |
| **Scale** | Multi-step automated pipeline, event-triggered |
| **Performance** | Near real-time trigger-to-message delivery |
| **Security** | API keys managed via environment credentials, no hardcoded secrets |
| **Impact** | Designed to recover otherwise-lost cart conversions through timed, personalized nudges |
| **Repository** | [View on GitHub](https://github.com/Abhinavsingh-16) |

This project mattered to me because it forced product framing onto a technical build: what's the user drop-off moment, what's the right timing for intervention, and how do you measure whether the nudge actually worked — not just whether the automation "runs."
